## Critical Fix: MetalLB exclude-from-external-load-balancers

Kubernetes 1.24+ automatically adds `node.kubernetes.io/exclude-from-external-load-balancers`
to control-plane nodes. MetalLB 0.14+ respects this and silently skips ALL LoadBalancer
BGP announcements — VIPs get IPs assigned but are never advertised into the fabric.

**Fixed in `form-k8s-cluster.py`**: automatically removes the label after cluster formation.

If you see VIPs assigned but `curl` hanging, check:
```bash
kubectl logs -n metallb-system -l app=metallb,component=speaker -c speaker 2>/dev/null | \
  grep "exclude-from-external-load-balancers"
# If this appears, run:
kubectl label node cp-1 cp-2 cp-3 node.kubernetes.io/exclude-from-external-load-balancers-
```

## Key Known Issues / Workarounds

**containerd 2.x config_path** — CP VMs' containerd has `config_path = '/etc/containerd/certs.d:/etc/docker/certs.d'` (colon-separated). Containerd 2.x treats this as a single literal path (not split), so certs.d is never found and registry pulls fail with HTTPS error. `setup-insecure-registry.py` now strips the second path. If it still fails, run manually:
```bash
for ip in <cp-1-ip> <cp-2-ip> <cp-3-ip>; do
  ssh ubuntu@$ip "sudo sed -i 's|:/etc/docker/certs.d||' /etc/containerd/config.toml && sudo systemctl restart containerd"
done
```

**DHCP lease rotation** — cp-dpu-1/2 may lose their OOB DHCP leases (leases now set to 7 days, but old deploys used 1h default). If check-vms.py shows "running (OOB IP not found)" for DPU stand-ins but CP hosts have internet, the DPU stand-ins ARE working. Use `virsh net-dhcp-leases oob-cp` to see current leases.

**ESO version** — Pinned to `0.14.3` (production version). ESO 2.x dropped v1beta1 which nico-prereqs requires.

**Vault** — dev mode (in-memory, root token = `root`). Restart loses all state.

**Postgres** — 3 instances to match production (synchronous_commit=remote_apply needs replicas).

## MAT Integration Verified (2026-08-05)

MAT running against dc-sim — virtual machines visible in Nico admin UI.

**Working flow:**
- MAT connects to `https://nico-api.nico-system:443` (→ VIP 7.133.1.17)
- Auth: SPIFFE cert `spiffe://nico.local/nico-system/sa/machine-a-tron` → Machineatron principal
- API-mode DHCP: Nico assigns IPs from `rack-mat-hosts` (7.136.0.0/16) underlay
- BMC mocks listening on 7.136.0.x:2000 (IP aliases on br-internet)
- Machines visible in Nico admin UI at https://7.133.1.17/admin

**Cert issuance (from site folder):**
```bash
mkdir -p mat
# CA
kubectl get secret nico-roots -n nico-system \
  -o jsonpath='{.data.ca\.crt}' | base64 -d > ./mat/mat-ca.pem
# Client cert with Machineatron SPIFFE identity
kubectl -n vault port-forward vault-0 8200:8200 &
sleep 2
curl -s -H "X-Vault-Token: root" -H "Content-Type: application/json" \
  -d '{"common_name":"machine-a-tron","uri_sans":"spiffe://nico.local/nico-system/sa/machine-a-tron","ttl":"720h"}' \
  http://127.0.0.1:8200/v1/nicoca/issue/nico-cluster > /tmp/mat-cert.json
python3 -c "
import json
d=json.load(open('/tmp/mat-cert.json'))['data']
open('./mat/mat-client.pem','w').write(d['certificate'])
open('./mat/mat-client-key.pem','w').write(d['private_key'])
"
kill %1 2>/dev/null
```

**run-mat.sh:**
```bash
FORGE_ROOT_CA_PATH=/path/to/site/mat/mat-ca.pem \
CLIENT_CERT_PATH=/path/to/site/mat/mat-client.pem \
CLIENT_KEY_PATH=/path/to/site/mat/mat-client-key.pem \
~/projects/infra-controller-core/target/release/machine-a-tron /path/to/site/mat-config.toml
```

**Key lessons:**
- `client_num_certs=0` in nico-api logs = MAT not sending cert (check paths)
- SPIFFE base path is `/nico-system/sa/` (from nico-api configmap)
- Machineatron principal required for GetDesiredFirmwareVersions, ForgeAgentControl etc.
- Admin UI password: `kubectl get secret nico-api-web-basic-auth -n nico-system -o jsonpath='{.data.password}' | base64 -d`
