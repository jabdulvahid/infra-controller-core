## Full Deploy Sequence

`deploy-nico-system.py` installs in this order, with 20s waits between each:

1. **local-path-provisioner** — Rancher; provides `local-path` StorageClass
   (kubeadm has none by default, needed for Vault PVC in prod mode)
2. **cert-manager** — jetstack/cert-manager v1.21.1
3. **vault** — dev mode (`vault.vault.svc.cluster.local:8200`, root token = `root`)
4. **external-secrets** — pinned to `0.20.4` (see above)
5. **postgres-operator** — sais/postgres-operator (Zalando)
6. **nico-prereqs** — `infra-controller-core/helm-prereqs` local chart
7. **nico** — `infra-controller-core/helm` umbrella chart

Vault is in **dev mode**: in-memory, auto-initialized, never needs unsealing,
root token hardcoded to `root`. Changed from production mode to avoid Vault
init/unseal complexity in simulation.

## ESO Wait Logic (current state in deploy_eso)

Three-phase wait after `helm upgrade --install external-secrets`:

1. `kubectl wait --for=condition=Established crd/<name>` for 3 CRDs
2. `kubectl apply --dry-run=server` of a ClusterSecretStore — this is the
   definitive gate: exercises the webhook + v1beta1 endpoint exactly as
   nico-prereqs helm will. Timeout: 180s.

If the dry-run wait times out, check:
```bash
kubectl get pods -n external-secrets
kubectl get crd clustersecretstores.external-secrets.io \
  -o jsonpath='{range .spec.versions[*]}{.name}: served={.served}{"\n"}{end}'
```

## All Fixes Applied (complete list)

| Area | Fix |
|------|-----|
| ESO version | Pin to `0.14.3` (production version from helmfile.yaml) — 2.x dropped v1beta1 |
| ESO CRDs on --destroy | Explicitly delete ESO CRDs so next install gets correct version's CRDs |
| ESO readiness gate | Replace dry-run checks with pod readiness check (3 pods Running) |
| Vault address | Use `http://` not `https://` for dev mode vault in generate-sim-values.py |
| nico image name | `7.131.0.7:5000/nico` not `7.131.0.7:5000` (chart renders `repo:tag` not `repo/image:tag`) |
| containerd 2.x | Use `certs.d/hosts.toml` format; remove old `registry.mirrors` entries from config.toml; fix `config_path` to single path (not colon-separated) |
| nico-system namespace | Pre-create with helm ownership labels before nico-prereqs; chart manages namespace |
| forge-system namespace | Set `legacyAlias.aliases[0].createNamespace: true` — doesn't pre-exist in simulation |
| Vault PKI init container | Job waited for HTTPS vault; dev mode is HTTP — fixed vault.address in gen_nico_prereqs |
| Postgres synchronous mode | Use 3 instances (match production) — 1 instance + `synchronous_commit=remote_apply` hangs writes |
| DHCP provisioningServer | Add `pxe_vip` to dc-sim.yaml; wire through `config.kea.hookParameters.provisioningServer` |
| nico-api resources | Reduce from 8Gi/32Gi to 1Gi/4Gi request/limit — CP VMs have 8Gi total RAM |
| SSH host key format | Pre-create `ssh-host-key` secret with `ssh-keygen` (OpenSSH format) — chart's `genPrivateKey` produces PKCS8 which ssh-console-rs rejects |
| Inter-component waits | 20s between each component to avoid API server race conditions |

## Root Cause of ESO v1beta1 Problem

ESO jumped to 2.x (chart version 2.8.0 = app v2.8.0) and set
`v1beta1: served=false`. Available chart versions:
- `2.x` (2.0.0–2.8.0): v1beta1 **NOT served**
- `1.x` (1.0.0–1.3.2): unknown, possibly OK
- `0.x` (0.14.0–0.20.4): v1beta1 served=true ✓

nico-prereqs uses `apiVersion: external-secrets.io/v1beta1` in:
- `helm-prereqs/templates/eso-external-secrets.yaml`
- `helm-prereqs/templates/eso-secretstores.yaml`
